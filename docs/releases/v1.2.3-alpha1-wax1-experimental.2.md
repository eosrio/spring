# Spring WAX profile v1.2.3-alpha1-wax1-experimental.2

> **Experimental prerelease — WAX Testnet and local development only.**
> Do not deploy this build to WAX Mainnet producers or treat the consensus-module
> API as stable. This release exists to gather independent replay, validation,
> packaging, security, and operational evidence from the Antelope community.

## Why this release supersedes experimental.1

Experimental.1 inherited the EOS-specific Business Source License file from the
EOSRIO 1.2.3 maintenance branch. Upstream AntelopeIO Spring moved the project to
the MIT License in commit
[`e6a99f68`](https://github.com/AntelopeIO/spring/commit/e6a99f68b67abc4d89fe716755b2e1394a4991f7)
on November 12, 2025, but that license-only change had not been imported into
the EOSRIO maintenance line.

This release synchronizes the root license with upstream's MIT text and uses a
new immutable tag and checksums. Experimental.1 remains available for
provenance but should not be used for WAX deployment or redistribution.

The artifacts intentionally retain the `wax1` package version so this
license-only correction preserves the exact consensus-profile manifest from
experimental.1. Existing experimental.1 Debian installations therefore require
an explicit reinstall of the experimental.2 package rather than a normal
version upgrade.

No consensus implementation changed between experimental.1 and this release.
The WAX module version and manifest hash remain:

```text
wax@1.0.3wax01
18f30c2ef041849ce691cd2a9f316d06abe5c58bf0fbd5b3bf6be2477a1d1aca
```

## What the experiment provides

The `wax@1` compile-time consensus profile isolates WAX's historical
`env.verify_rsa_sha256_sig` intrinsic from the shared Spring implementation.
The same source tree can therefore produce two separately named builds:

| Profile | Package | Consensus modules |
| --- | --- | --- |
| `vanilla@1` | `antelope-spring` | none |
| `wax@1` | `antelope-spring-wax` | `wax@1.0.3wax01` |

The WAX profile is not bound to a production chain ID, allowing WAX-compatible
applications to be tested on arbitrary local development chains. It is a
compile-time consensus module rather than an appbase plugin or dynamically
loaded library: every validating node must run the same profile.

## Validation evidence

The consensus implementation is identical to experimental.1, for which the
following validation was completed:

- the original WAX RSA suite passed 67 of 67 assertions under EOS-VM and
  EOS-VM-JIT;
- module compatibility tests passed under EOS-VM, EOS-VM-JIT, and EOS-VM-OC;
- the vanilla profile rejected the WAX intrinsic import;
- the exact WAX Testnet block `419439156` ORNG RSA vector passed under all three
  runtimes;
- the packaged node restored snapshot block `419754590`, synchronized through
  four peers, and passed clean restarts;
- a live request from `waxspringexp` completed the full
  `requestrand -> setrand -> randnotify` flow;
- oracle transaction
  `4c0b3d4d987e5e696f9f9efaf035886216264e61a8fad5b25c4b5df679871207`
  was accepted in block `419806003`, invoked the RSA intrinsic, delivered die
  result `3`, and became irreversible;
- the rebuilt archive and Debian package report the tagged commit, `wax@1`
  profile, and unchanged manifest hash;
- the Debian package installs and passes `nodeos --full-version` smoke tests in
  clean Ubuntu 22.04 and Ubuntu 24.04 containers.

The live ORNG exercise used the example from
[`worldwide-asset-exchange/wax-orng`](https://github.com/worldwide-asset-exchange/wax-orng/tree/7b84fede311db5a2f4d26bfb441ba5bebf751f9f/example)
at commit `7b84fede311db5a2f4d26bfb441ba5bebf751f9f`.

- `antelope-spring-wax-1.2.3-alpha1-wax1-x86_64.tar.zst`

Verify downloads before installation:

```sh
sha256sum --check SHA256SUMS.txt
```

After installation, verify the selected profile:

```sh
nodeos --full-version
curl -s http://127.0.0.1:8888/v1/chain/get_info | jq '{
  server_full_version_string,
  server_consensus_profile,
  server_consensus_module_manifest,
  server_consensus_manifest_hash
}'
```

Spring's chainbase database environment signature includes compiler details.
When changing compiler or other chainbase environment parameters, restore a
snapshot or replay into a fresh data directory rather than copying an existing
`state` directory.

## Known limitations

- A full genesis-to-head WAX replay and long-duration producer soak test have
  not yet been completed.
- Multiprecision modular exponentiation remains controlled by contract input
  without a dedicated deterministic work limit. This preserves deployed WAX
  behavior but requires focused resource-exhaustion review before production.
- The consensus-module API, manifest schema, profile versioning policy, and
  `get_info` fields remain experimental.
- This release has not been audited as a production consensus implementation.

Please report test results and failures through the EOSRIO Spring issue tracker.
Include the operating system, runtime, snapshot or replay starting block, full
node version, manifest hash, and relevant logs. Never include signing keys or
private peer credentials.
